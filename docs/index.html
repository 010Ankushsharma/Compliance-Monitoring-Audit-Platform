Features

Everything in one place. Nothing extra.

Every component built with the same precision you expect from enterprise security tooling — no compromises.

01
🔗
SHA-256 Hash-Chained Audit Trail

Every action is hashed and chained to the previous entry. Immutability enforced at two layers — a PostgreSQL trigger rejects UPDATE/DELETE, and the JPA entity throws on modification. A single /verify-chain call walks the entire chain and reports broken links.

02
📊
Weighted Risk Scoring

CRITICAL=40pt, HIGH=25pt, MEDIUM=15pt, LOW=5pt. Score recalculates asynchronously via Kafka after every status change.

03
⚡
Event-Driven Architecture

Idempotent Kafka producers, manual-ack consumers, and Dead Letter Topics with 3-retry error handling. Zero audit latency on request threads.

04
🔐
5-Level RBAC

SUPER_ADMIN · COMPLIANCE_OFFICER · AUDITOR · ANALYST · API_CLIENT. JWT/HS512 with rotating refresh tokens. BCrypt-12 passwords. Account lockout.

05
🔔
Smart Alert Deduplication

Deterministic dedupKey prevents duplicate storms. Auto-escalation: CRITICAL→1h, HIGH→4h. Email, Slack, and webhook channels.

06
📄
Async Report Generation

PENDING → GENERATING → COMPLETED via Kafka. PDF (iText 8), Excel (POI), CSV, JSON. Pre-built templates for all 6 frameworks.

01 / AUDIT TRAIL

Immutable. Tamper-evident.
Cryptographically chained.

Every platform action — login, policy change, data access, report generation — is recorded as an immutable audit log entry. Each entry's SHA-256 hash is computed over its own fields plus the previous entry's hash, forming a chain that detects any tampering instantly.

Two independent immutability layers: a database trigger rejects all UPDATE and DELETE statements, and the JPA entity's @PreUpdate throws an exception. Both must be bypassed to tamper with a record.

02 / VIOLATIONS

From detection to resolution.
A complete workflow.

Violations follow a strict state machine — OPEN → IN_REVIEW → RESOLVED, or FALSE_POSITIVE, or SUPPRESSED. Domain methods enforce every transition with business rules. A grace-period window prevents the same rule from generating duplicate violations.

Every violation captures a full JSONB evidence snapshot at detection time. Evidence files (screenshots, exports, logs) can be attached up to 50 MB per file.

03 / REPORTS

Generate compliance evidence.
While you sleep.

Report generation is fully asynchronous. A request creates a PENDING row, dispatches a Kafka message, and returns immediately. The generation consumer picks it up, runs through the evidence, writes the file, and updates the status to COMPLETED.

If a generation job gets stuck, a recovery scheduler detects it within 10 minutes and marks it FAILED with the error message — no silent hangs.

Quick Start

Running in under five minutes.

Docker Compose orchestrates PostgreSQL, Redis, and Kafka automatically. No external dependencies to install.

01
Clone the repository
Fork or clone directly. The Maven wrapper mvnw is included — no Maven install required.
02
Set environment variables
Copy .env.example to .env and generate a secure JWT secret using openssl rand -base64 64.
03
Start all services
One command starts everything — app, PostgreSQL, Redis, and Kafka. Flyway runs migrations and seeds all six framework policies automatically.
04
Login and explore
Swagger UI at localhost:8080/swagger-ui.html. Default: admin@company.com / Admin@1234. Change password immediately.
terminal
# Clone git clone https://github.com/010Ankushsharma/\ Compliance-Monitoring-Audit-Platform.git cd Compliance-Monitoring-Audit-Platform # Configure cp .env.example .env echo "JWT_SECRET=$(openssl rand -base64 64)" >> .env # Start everything docker-compose up -d Starting postgres ... done Starting redis ... done Starting kafka ... done Starting compliance-app ... done # Login curl -X POST localhost:8080/api/v1/auth/login \ -d '{"email":"admin@company.com", "password":"Admin@1234"}' {"accessToken":"eyJhbGci...", "role":"SUPER_ADMIN"} # Swagger UI open http://localhost:8080/swagger-ui.html
